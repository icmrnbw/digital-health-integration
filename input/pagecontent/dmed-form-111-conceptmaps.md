# DMED 111: ConceptMap

Source: `form_111_mapping_valuesets_complete_ru.xlsx`, ConceptMaps (112 source rows). Repeated identical mappings are deduplicated. Existing split CodeSystems are used instead of the obsolete umbrella URI. ICD-10 fields use the original ICD-10 coding without enumerating the dictionary: pregnancy_complications, gynecological_diseases, diagnosis_icd10, icd10_diagnosis / functional_icd10_diagnosis.

Blood group targets corrected using https://hl7.org/fhir/uv/ips/STU1.1/ValueSet-results-blood-group-snomed-ct-ips-free-set.html. The source workbook contains incorrect ABO/Rh code assignments.

Training: https://dmed.notion.site/111-3a060b77fbf580c885b1e1b3e7c7c371

Browser checks 2026-09-11 and 2026-09-14: existing test pregnancy episode → Form111 → gynecologist examination, family/sexual history, first examination, gynecological examination, pregnancy-week sections. Dialogs closed without saving. Radio values and client component agree for ABO/Rh, contraception type, breast condition, vascular status and three fetal-presentation values. Non-surgical contraception exposes six methods; surgical exposes the two methods defined in the component. Full risk-category dictionaries were checked against the browser-loaded client source. In the 16-week dialog, the four preparation-for-childbirth controls (physical exercise, ultraviolet irradiation, mothers' school and psychoprophylactic preparation) are date inputs with `ДД.ММ.ГГГГ` placeholders, not terminology dropdowns; no ConceptMap is required for them. This verifies available fields/tokens and control types, not server persistence or clinical FHIR validation.

Education: the current client includes 17 tokens, more than the workbook's three. All are retained in source coverage. Every token now has a national education-cs target. `higher_specialist` uses the existing `regis0005.00012` Specialty code; postgraduate, residency and internship retain their precise DMED source coding alongside the broader national Higher education code. Because the national system has no direct Primary general education or Professional development category, those two values use national Other plus the precise source coding. The local Form 111 CodeSystem remains an optional second coding where a local target exists; a local code alone does not satisfy UZCoreSocioeconomicObservation.

Browser re-check 2026-09-16: `previous_pregnancies[].birth_type` uses `vaginal_delivery` / `surgical_delivery`; `child_birth_status` uses `preterm` / `term`; and `child_birth_condition` uses `live_birth` / `stillbirth_antenatal` / `stillbirth_intranatal`. The current client visibly swaps the labels for the two `child_birth_status` tokens, so the ConceptMap follows token semantics and records the UI defect instead of reproducing it. `patient_detail.family_status` exposes six tokens; `other` remains noMap because v3-MaritalStatus has no generic other code. The analyses dialog accepts free-text results, so `analysis_title=OTHER` remains an adapter fallback rather than a complete laboratory terminology map.

The shared `blood_group` and `rhesus_factor` source systems apply to both `patient_detail.blood_type` / `patient_detail.rh_factor` and the partner fields in `family_sexual_history`. The two education ConceptMaps also share the single `education_type` source CodeSystem; `education-type-core` is a second target mapping, not a second DMED field or vocabulary.

The full repository build has pre-existing Standalone.fsh translation-extension errors (436–444), also documented in the earlier review task. New terminology is compiled separately and its local targets checked. Source fields marked as grouped booleans in the workbook retain their boolean contract; these maps do not turn missing data into false.

Source CodeSystems use `content = fragment`: coverage is limited to the explicitly verified fields. Unknown tokens must be retained for review, never silently mapped. `noMap` means there is no approved target in this deliverable. Boolean JSON values stay boolean in the integration; the lexical tokens `true`/`false` are only terminology mapping inputs.
